## 📚 学习路线 & 关键源码

> **阅读原则**：只关注运行时真正被执行的代码（约 20%），其余代码可在需要时再回顾。

### 第一阶段：启动流程（1~3 天）

| 步骤 | 源码路径 | 关键函数/类 | 任务 |
|------|----------|--------------|------|
| 1️⃣ `main.ts` → `NestFactory.create()` | `packages/core/nest-factory.ts` | `NestFactory.create` | 在 `main.ts` 中添加打印日志，观察 `NestFactory` 调用栈 |
| 2️⃣ `NestApplicationContext` 实例化 | `packages/core/application-context.ts` | `NestApplicationContext` | 读取构造函数，找出 `container`、`instanceLoader`、`moduleCompiler` 的初始化 |
| 3️⃣ `InstanceLoader` 加载模块 | `packages/core/instance-loader/instance-loader.ts` | `loadInstance`、`loadProviders` | 在 `loadProviders` 前后加 `console.time`，定位实际执行顺序 |
| 4️⃣ DI 初始化 | `packages/core/injector/` | `Injector`, `Container` | 用 VSCode “调试 → 断点” 跟踪 `container.get` 的调用路径 |
| 5️⃣ HTTP Server 启动 | `packages/platform-express/adapters/express-adapter.ts` | `listen` | 观察 `express` 实例如何被包装成 Nest 应用 |

> **练手**：在 `NestFactory.create` 前后分别插入自定义插件（`app.useGlobalPipes`），观察插件在启动链路中的位置。

### 第二阶段：DI 依赖注入（1~2 周）

| 关注点 | 源码路径 | 关键概念 |
|--------|----------|----------|
| Provider 注册 | `packages/core/injector/provider.ts` | `useClass`, `useValue`, `useFactory`, `useExisting` |
| Token 解析 | `packages/core/injector/tokens.ts` | `ModuleTokenFactory`、`Injectable` |
| Scope（Singleton/Transient/Request） | `packages/core/injector/instance-wrapper.ts` | `InstanceWrapper.scope` |
| 循环依赖检测 | `packages/core/injector/circular-dependencies.ts` | `isCircularDependency` |
| 运行时实例化 | `packages/core/injector/injector.ts` | `resolvePerContext`、`loadInstancePerContext` |

> **练手任务**  
1. 编写自定义 `Scope`（例如 `SessionScope`），并在 `Container` 中注册。  
2. 用 `Reflect.getMetadata` 手动读取 `@Injectable` 的 metadata，验证其结构。  
3. 设计一个 **“懒加载 Provider”**（在第一次请求时才实例化），观察对启动时间的影响。

### 第三阶段：Module 系统（3~5 天）

| 关键路径 | 关注点 |
|----------|--------|
| `module.ts` | `imports`, `exports`, `providers`, `controllers` 的注册流程 |
| `module-reflection.ts` | `@Module` 装饰器元数据收集 |
| `module-graph.ts` | 模块依赖图的构建、循环依赖检测 |
| `module-compiler.ts` | 动态模块（`registerAsync`）的实现细节 |

> **练手**：实现一个 **“插件模块”**，能够在运行时通过 `app.select(Module).addProvider(...)` 动态注入 Provider。

### 第四阶段：装饰器系统（1 周）

| 装饰器 | 源码路径 | 说明 |
|--------|----------|------|
| `@Controller`、`@Get`、`@Post` | `packages/common/decorators/` | 装饰器本质是向 class / method 写入 metadata |
| `@Injectable` | `packages/common/decorators/injectable.decorator.ts` | 记录 provider 信息 |
| 自定义装饰器 | 任意 | 通过 `Reflect.defineMetadata` 与 `Reflect.getMetadata` 实现 |

> **练手**：实现 `@Roles(...roles:string[])` 装饰器，配合 Guard 实现基于角色的访问控制。

### 第五阶段：请求生命周期（1 周）

| 环节 | 源码路径 | 关键类 |
|------|----------|--------|
| Middleware | `packages/core/middleware/` | `MiddlewareConsumer` |
| Guard | `packages/core/guards/` | `GuardConsumer` |
| Pipe | `packages/core/pipes/` | `PipeConsumer` |
| Interceptor | `packages/core/interceptors/` | `InterceptorConsumer` |

> **练手**：编写完整的请求流水线 Demo，包含日志 Middleware、Auth Guard、Validation Pipe、Result Interceptor，使用 `app.useGlobalFilters` 替代默认异常处理。

### 第六阶段：手写 Mini‑Nest（2~3 周）

| 步骤 | 产出 | 说明 |
|------|------|------|
| 1️⃣ 实现最小 DI 容器 | `container.ts` | 支持 `useClass`、`useValue`、`Singleton`、`Transient` |
| 2️⃣ 实现路由系统 | `router.ts` | 基于 `express` 或 `fastify`，解析 `@Controller/@Get` 元数据 |
| 3️⃣ 实现装饰器 | `decorators.ts` | `@Injectable`、`@Controller`、`@Get` |
| 4️⃣ 实现中间件管道 | `pipeline.ts` | Middleware → Guard → Pipe → Handler → Interceptor |
| 5️⃣ 单元测试 | `__tests__/` | 用 `jest` 覆盖每个核心模块 |
| 6️⃣ 文档 & 示例 | `README.md` | 快速上手指南、对比官方 NestJS 实现的差异 |

> **评估标准**  
- ✅ 能够通过 `npm link` 在另一个项目中使用你的 Mini‑Nest  
- ✅ 支持 **动态模块** 与 **全局拦截器**  
- ✅ 完整的 **CI**（GitHub Actions）+ **测试覆盖率 ≥ 80%**

## 🛠️ 实践技巧 & 常见坑

| 场景 | 常见问题 | 解决方案 |
|------|----------|----------|
| **调试源码** | 打断点不生效（ts-node 编译后） | 使用 `npm run build` 生成 `dist`，在 `launch.json` 中配置 `"sourceMaps": true`，并确保 `tsconfig.json` `sourceMap:true` |
| **循环依赖** | `Cannot resolve dependency` 报错 | 检查 `forwardRef(() => ...)` 是否缺失；在 `Container` 中查看 `isCircularDependency` 调用栈 |
| **Scope 错误** | Request‑scoped provider 变成 Singleton | 确认 `Module` 的 `providers` 中 `scope: Scope.REQUEST` 正确设置；使用 `app.useGlobalGuards` 时保持同一请求上下文 |
| **自定义装饰器** | `Reflect.getMetadata` 返回 `undefined` | 检查 `tsconfig.json` 中 `experimentalDecorators` 与 `emitDecoratorMetadata` 必须为 `true` |
| **动态模块** | `moduleRef.get` 返回 `undefined` | 确保 `exports` 中已经导出该 Provider，或使用 `moduleRef.create` 手动实例化 |
| **Mini‑Nest** | 路由匹配不到 | 检查 `router.register` 时路径前后是否多余 `/`，以及 `method` 是否全大写（GET/POST） |

## 🎯 最终项目（可选）

**项目名称**：`NestMiniBlog`  
**目标**：使用自己实现的 Mini‑Nest 完成一个简易博客系统，包含：

1. 用户注册 / 登录（JWT Guard）  
2. 文章 CRUD（全局管道校验）  
3. 评论模块（动态模块加载）  
4. 插件系统：实现一个 “访问统计” 插件，记录每个路由的请求次数并通过 Interceptor 返回 Header  

**评估指标**：

| 项目 | 评分标准 |
|------|----------|
| **功能完整性** | 所有 RESTful 接口返回符合预期的 HTTP 状态码 |
| **代码结构** | 与官方 Nest 项目结构保持一致（module → controller → service） |
| **DI 正确性** | 没有循环依赖，Scope 正确使用 |
| **测试覆盖率** | `jest` 单元测试覆盖率 ≥ 80% |
| **文档** | README 中包含启动步骤、插件使用说明、与官方 Nest 对比的实现差异 |

完成该项目后，你将具备 **“从源码到实战、再到自研框架”** 的完整闭环能力。
